# 02 · 算力峰值（ALU / XMX-DPAS）基准报告

- tag: `20260922-192831`
- time: 2026-09-22T19:34:05
- host: hwt / kernel 6.14.0-37-generic / python 3.13.3
- ZE_AFFINITY_MASK: `(unset)`
- 标称 FP32 ALU 峰值（公式）: 22.22 TFLOPS

## 关键结论速览

- ALU 向量宽度扫描：VEC≥4 后饱和 → 说明该循环是 **issue 受限** 而不是宽度受限。
- XMX 原始 DPAS 实测：bf16 **355 TFLOPS**、int8 **710 GOPS**（int8/bf16 = 2.00×，符合 K=32 vs K=16 的 2× 关系）。
- ⚠ XMX 探针的**绝对吞吐不可信**：sub-group 数 ×2 而耗时不变（work-group ×2.00 时耗时 ×1.00 （期望 ≈×2.00））。数值正确性（CHECK）与「DPAS 可用」的结论仍然成立，但峰值请以 oneDNN GEMM 为准。
- XMX 探针的 FLOP 计数对 NACC 线性、耗时也对 NACC 线性 → **计数口径本身自洽**；问题出在 work-group 数维度上（见 consistency_check）。
- **oneDNN GEMM（可信口径）**：fp32 22.1 TFLOPS（= 标称 22.2 的 100%）、bf16 226.6、fp16 223.6、int8 427 GOPS。
- ⚠ 主频锁定 **1550 MHz**（min=max=act），但纯 FMA 实测 **50.7 TFLOPS** = 公式值 22.22 的 **2.28×**。「实测 > 标称」无法用主频解释 → 标称公式里的 EU/lane 数与本 ES 部件不符。
- 标称 FP32 ALU 峰值（公式 448 EU × 16 lane × 2 × 1.55 GHz）= **22.22 TFLOPS**。主频可读且锁定在 1550 MHz，但实测显著高于公式值 → 见 clock/implied_exec_width。
