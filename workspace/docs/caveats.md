# 风险与注意事项

本页汇总勘察中发现的、**会直接影响性能测试可信度**的问题。测试前请先读这一页。

---

## ⚠️ 1. CPU 与 GPU 均为 ES 工程样品

| 证据 | 说明 |
|---|---|
| GPU：`SKU Type: Production ES` | 两张卡都是工程样品 |
| CPU：`Model name: Genuine Intel(R) 0000` | 型号被掩码，典型 pre-production 表现 |
| CPU：基频仅 2.7 GHz，`BIOS Model name` 带 `0000` 占位 | 同上 |

**影响**：
- 绝对性能数字**不适合直接对外宣传**或与量产机型做横向对比
- 可能存在未公开的性能/稳定性问题（如降频、固件缺陷）
- **建议**：报告中明确标注 "测试平台为 ES 样片"，结论以**相对比较**（如双卡 vs 单卡扩展效率、FP32 vs BF16 加速比）为主，弱化绝对值

---

## ⚠️ 2. 主机内存严重小于 GPU 显存（内存倒挂）

| 项目 | 容量 |
|---|---|
| 主机 DRAM | **45 GiB** |
| 两卡 HBM 合计 | **96 GiB** |

**影响**：
- 大模型权重、大规模数据集无法在 host 侧完整驻留
- host↔device 数据搬运、CPU 预处理、DataLoader 极易成为瓶颈
- 单 NUMA 节点 → 无法通过 NUMA 亲和性调优缓解

**建议**：
- 所有 GPU 测试**同步记录 CPU 占用率与 host 内存带宽**（`/usr/bin/stream`）
- AI 训练测试中把 DataLoader worker 数、pin_memory、数据传输时间单独打点
- 若发现 GPU 利用率偏低，**优先排查 host 侧而非 GPU**

---

## ⚠️ 3. Xe Link 未标定

```
Xe Link Calibration Date: Not Calibrated
```

**影响**：
- 卡间实测带宽可能低于理论 304 GiB/s
- 多卡扩展效率可能异常偏低

**建议**：
- 卡间通信测试**先做**，作为后续多卡测试的前置基线
- 若实测达成率 < 70%，先排查标定问题，再判断硬件缺陷
- 向供应商确认 ES 样片上该状态是否正常、是否需要专用标定工具

---

## ⚠️ 4. 无媒体引擎

```
Number of Media Engines: 0
Number of Media Enhancement Engines: 0
```

**影响**：视频编解码 / 转码类测试**不可行**，相关指标恒为 `N/A`。

**建议**：测试清单中**移除** FFmpeg/QSV/VA-API、Deep-Link 转码类项目。

---

## ⚠️ 5. 频率被锁定在 1550 MHz

| 项目 | 值 |
|---|---|
| GPU Min Frequency | 1550 MHz |
| GPU Max Frequency | 1550 MHz |

min == max，说明**当前频率被钉死在 1550 MHz**（不是动态调频，或调频范围被人为收窄）。

**影响**：
- 无法观察到睿频带来的性能波动，测试重复性好（这反而是好事）
- 但也意味着**测不到真实量产环境下的动态功耗/频率行为**
- 功耗控制（`--powerlimit`）与频率控制的交互效果需专门测试

**建议**：
- 做功耗-性能扫描时，用 `--frequencyrange` 显式放开来测
- 记录锁频状态，避免把「锁频」带来的稳定当成「散热良好」

---

## ⚠️ 6. oneAPI 多版本并存

`compiler` 有 2025.3 / 2026.0 / 2026.1，`mkl` 有 2026.0 / 2026.1，`mpi` 有 2021.17 / 2021.18，而 `dnnl` 只有 2026.0。

**影响**：
- 不同测试可能隐式使用不同版本，结果不可比
- 定位性能回归时版本信息容易混淆

**建议**：
- 每个测试报告**必须记录**：`icpx --version`、`mpirun --version`、实际库路径
- 需要严格可比时，用 `setvars.sh` 显式指定版本

---

## ⚠️ 7. 驱动走 i915 而非 xe

```
lsmod: i915, i915_compat, i915_spi
```

Ponte Vecchio 在新内核上通常推荐 `xe` 驱动。当前使用传统 `i915` 路径。

**建议**：
- 查阅 `I915_25.2.57` 对 Max 1100 的支持矩阵
- 若遇到部分高级特性不可用（如某些 P2P / 内存属性），考虑到可能是驱动路径限制
- 可考虑**对比测试** i915 vs xe 两种驱动的性能差异（需谨慎，涉及驱动切换风险）

## ⚠️ 8. 其他观察

| 项目 | 观察 | 影响 |
|---|---|---|
| 空闲功耗 43 W | 相对较高 | 做能效对比时需扣除底噪 |
| `intel-gpu-ubuntu-noble-2523.run` 在 `/root/` | 驱动包仍留在 home | 说明使用 `.run` 方式安装，覆盖升级需重跑 |
| 主机内存已用 4 GiB / buff-cache 33 GiB | cache 占比较多 | 大测试前建议 `sync && echo 3 > /proc/sys/vm/drop_caches` 获得干净基线 |
| 无 HPL/HPCG 预装 | | HPC 测试需自行准备 |
| 只有一个 GPU 空闲进程（systemd-logind） | 基本无干扰 | 测试环境干净 ✅ |

## 测试可信度检查清单

每次出正式报告前，逐项确认：

- [ ] 是否已标注平台为 **ES 样片**
- [ ] 是否记录了 **oneAPI 各组件实际版本**
- [ ] 是否记录了 **驱动版本与 `xpu-smi` 版本**
- [ ] 是否确认 **Xe Link 标定状态**（若做多卡测试）
- [ ] 是否同步采集了 **host CPU / 内存带宽**（若做 AI 或数据密集测试）
- [ ] 是否记录了 **功耗约束**（Power Limit 300 W 是否被修改）
- [ ] 是否记录了 **频率状态**（锁定 1550 MHz）
- [ ] 是否清空了 **filesystem cache** 得到干净基线
- [ ] 是否至少跑 **3 次** 并给出中位数与离散度
- [ ] 是否在**满载稳态**（而非启动瞬态）采样遥测
